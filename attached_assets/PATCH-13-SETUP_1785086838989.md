# Patch 13 — Storyboards on every video engine

Applies on top of Patch 12 (`9a161a9`). One commit, no new dependencies, no
schema changes, no new environment variables.

## Why you saw no storyboard

Patch 12 only paused a job when two things were true at once: the engine was
Topic to Video, **and** the visuals were AI stills or a locked character. The
studio defaults topic videos to stock footage, so the toggle was hidden and
nothing ever paused. The other three engines had no planning step at all, and
the job id being held in memory meant a page reload orphaned a paused job.

All three are closed here.

## Installing

```
git apply patch-13-storyboard-all-engines.patch
pnpm install          # nothing new, but keeps the lockfile honest
pnpm --filter @workspace/db run push
```

`push` will report no changes — the storyboard column already exists and only
its TypeScript shape widened. Run it anyway so the test suite's schema check
agrees with the database.

## What each engine now plans

Text to Video asks for 1–5 shots up front. One shot behaves exactly as before.
More than one and the brief is split by the language model into that many
consecutive shots, each rendered separately and joined into a single video,
with the subject, wardrobe, location and visual style carried across the cut.
Image to Video shows the uploaded photo with what it should do and how long it
animates. Slideshow shows every photo with its own caption and hold time.
Topic to Video is unchanged except that the toggle is no longer hidden when
stock footage is chosen — it simply isn't offered there, because stock clips
are searched rather than prompted, so there is no prompt to edit.

Scene lengths are editable wherever nothing has been voiced yet: a clip holds
between three and ten seconds, a slide between one and ten. Where narration
has already been recorded the lengths follow the audio and are read-only —
editing one would desync every scene after it. Redraw is offered only on
stills that were generated; a slide or photo preview is the user's own upload,
and a shot list has no still to redraw.

## Billing

A multi-shot clip is priced at one video unit per shot, reserved at enqueue.
Turning review off does not turn a three-shot job into a one-shot job — it
plans in memory and renders in one pass, so the shots that were paid for are
the shots that get delivered. Nothing beyond that reservation is metered until
a plan is approved, and a plan left unapproved is swept and refunded after a
day.

## The review window

The storyboard opens by itself as soon as the plan lands, as a dialog over the
studio. Dismissing it leaves an **Open storyboard** button on the job card, and
the newest waiting plan is picked up again after a reload, so a paid-for plan
cannot be lost by closing the tab. **Render** saves whatever is on screen
before it starts — an edit typed and not saved is never filmed without.

## Still to come

Topic videos using stock footage have no storyboard. Reviewing one means
holding the found clips somewhere between planning and approval; parking
third-party URLs in a blob the browser can edit would turn approval into a
server-side fetch of a user-influenced host, which is the same risk that ruled
out reference videos by URL. Doing it properly means copying the chosen clips
into your own storage at planning time. That is a patch of its own.
