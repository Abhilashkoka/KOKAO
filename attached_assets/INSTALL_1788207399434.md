# KOKAO lip-sync patches — install order

Seven patches. Apply **in order**; each builds on the one before.

Verified on a clean clone of `main` (8138eabe): all seven apply with
`git am`, api-server typecheck is clean, and 463/463 tests pass
(videoGen + the generate-video route suite) against a real Postgres
with the schema pushed.

## Apply

From the repo root, in the Replit shell:

```bash
git apply --check 0001-*.patch          # dry run — silence means clean
git am 0001-*.patch 0002-*.patch 0003-*.patch \
       0004-*.patch 0005-*.patch 0006-*.patch 0007-*.patch
```

If `git am` complains, `git apply <file>` each in order and commit normally.

Then, because patches 2 and 7 add columns:

```bash
pnpm --filter @workspace/db run push    # additive, no data loss
```

No new npm dependencies.

## What each one is

| # | Patch | Phase |
|---|---|---|
| 1 | Fit the base video to the narration before lip-syncing | 0 — repair |
| 2 | Refuse hopeless lip-sync sources and make the model swappable | 0 — repair |
| 3 | Add an offline lip-sync inspection script | 0 — repair |
| 4 | Add narration slicing and exact shot trimming | 1 — slice |
| 5 | Stop the timeline from desyncing lip-synced shots | 1 — slice |
| 6 | Lip-sync character scenes to the narration | 1 — slice |
| 7 | Price, gate and time-box spoken character videos | 1 — slice |

**Patches 1-3 stand alone.** They fix the lip-sync engine you have in
production today. You can stop after 3, ship, and come back later.

**Patches 4-7 add character lip sync**, and land nothing user-visible
until you switch it on (see below). 4 and 5 are pure plumbing and
safety; 6 wires the feature; 7 prices and gates it.

## After patch 3 — verify the production repair

Re-run a lip-sync job on the doctor clip, then:

```bash
node scripts/src/lipsync-inspect.mjs <downloaded.mp4>
```

It finds every pause in the narration and writes one contact sheet per
pause. Nobody is speaking in any frame of those sheets — an open,
changing mouth means the sync is still wrong. On your current sample it
found three pauses, and the mouth was wide open through the first.

Also worth checking: the output should now be 720p or better where it
used to be 478p, and its length should match the narration.

## After patch 7 — switching character lip sync on

It is **off by default**, on purpose: it doubles the price of a
character video (Short 4→8 units, Medium 8→16, Long 12→24), and a
deploy should not do that to existing tenants silently.

To turn it on, either set the env var:

```
CHARACTER_LIPSYNC=1
```

or flip the stored setting:

```sql
UPDATE video_gen_settings SET character_lip_sync = true WHERE id = 1;
```

The existing `lipSync` kill switch still applies on top — both paths
spend on the same model, so both stop at the same switch.

## Comparing lip-sync models

Patch 2 lifts the pinned LatentSync build out of its call site, so you
can A/B without a deploy:

```
LIPSYNC_MODEL=owner/name:version
```

or `UPDATE video_gen_settings SET lip_sync_model = '...' WHERE id = 1;`

Empty or unset keeps the pinned default. Job rows record whichever
model actually ran.

## What is deliberately NOT here

An automated sync check inside `verifyRenderedVideo`. The ffmpeg-only
measurements available to that gate do not separate a synced mouth from
an unsynced one — on your real failing sample, mouth-band motion during
silence measured 2.0-3.0x global motion and during speech 2.1-3.2x,
completely overlapping, because head and hand movement swamp the mouth.
A gate built on that would fail good jobs and refund credits for
nothing. Patch 3's script does the tedious part instead and leaves the
judgement to a person.

Also not here: the cast, per-character voices, and dialogue scripts
(phase 2). Those need the speaker-turn cut points and a scene-count
pricing change, and they are worth doing after you have seen a real
spoken character render.
