## ⚠️ Correction to Program A — read this first

`artifacts/api-server/src/routes/gamification.ts` calls
`getReferralStats(req.tenantId)` with one argument, and returns
`captionCreditsEarned` / `imageCreditsEarned` in its response. Program A's
Edit 5b changes that signature and removes those fields, so **that route stops
compiling** unless it's updated in the same pass.

I flagged "grep `getReferralStats(`" in the Program A setup; this is the caller
it finds. Here is the fix.

In `routes/gamification.ts`, inside `GET /gamification/referral`:

```ts
  let stats;
  try {
    stats = await getReferralStats(req.tenantId, tenant.plan);
  } catch (error) {
    res.status(422).json({
      error:
        error instanceof Error
          ? error.message
          : "Referral history is unavailable.",
      code: "reward_mapping_missing",
    });
    return;
  }
  res.json({
    code: code.code,
    refereeCredits: refereeCreditsMilli / MILLI,
    referrerCredits: referrerCreditsMilli / MILLI,
    maxRedemptions: code.maxRedemptions,
    // Purchase-triggered stats replace the old redemption counts.
    attributedWorkspaces: stats.redemptions,
    qualifyingPurchases: stats.qualifyingPurchases,
    creditsEarned: stats.creditsEarned,
    grossDriven: stats.grossPaise / 100,
    currentReferrerBps: stats.currentReferrerBps,
    nextSlabAt: stats.nextSlabAt,
    nextSlabBps: stats.nextSlabBps,
  });
```

Delete the now-unused `refereeCaptionCredits` / `refereeImageCredits` /
`referrerCaptionCredits` / `referrerImageCredits` keys from that response, and
update the web app's referral card to match.

## What's in this bundle

```
artifacts/api-server/src/routes/promoter.ts        tenant-facing
artifacts/api-server/src/routes/promoterAdmin.ts   superadmin
```

Conventions followed from `routes/gamification.ts` and `routes/index.ts`:
`Router()` typed as `IRouter`, `req.tenantId` from `requireTenant`, `req.log`
for errors, `{ error, code }` response shape, `export default router`.

**Validation schemas are declared locally** so both routers compile before the
OpenAPI contract is updated. Once the paths are in the contract and codegen has
run, swap them for the generated bodies from `@workspace/api-zod` — the way
`gamification.ts` imports `ClaimGamificationRewardBody`. The repo runs a codegen
drift check, so do this before opening a PR.

```ts
router.use("/promoter/apply", sensitiveLimiter);
```


`promoterAdminRouter` applies `requireSuperadmin` to its own path prefixes
internally, so it is deliberately **not** behind `requireFeature` — a disabled
program must still be re-enablable from the admin UI, matching how
`adminRouter` is treated.

## Two deliberate choices in the response shapes

**Referred workspaces are masked.** `GET /promoter/commissions` returns
`"Workspace #4821"` — never a name or email. A promoter earning from someone
does not entitle them to know who that someone is, and not returning it means
there is no leak to get wrong later.

**Risk detail is never exposed.** A held commission reads as `"Under review"`.
It does not say which signal tripped, because telling someone exactly which
check caught them is how you teach them to evade the next one.

---

## The UX contract

`GET /promoter/me` drives the entire entry point with its status code:

| Response | Show |
|---|---|
| **404** `not_a_promoter` | The "Become a promoter" card |
| **200** `status: applied` | Pending review state, application summary |
| **200** `status: approved` | Dashboard: code, earnings, tier progress |
| **200** `status: rejected` | The reason, no code |
| **200** `status: suspended` | Suspended notice, earnings still visible |
| **403** `feature_disabled` | Hide the nav item entirely |

One endpoint, six states. The frontend needs no other call to decide what to
render.

**The earnings block is the important one.** `awaitingActivation` and
`inHoldWindow` exist so the dashboard can say *"₹4,200 pending — 3 awaiting
activation, 2 in hold"* rather than an unexplained number. Promoters tolerate
delay they can see and churn from delay they can't, and it makes the rules
defensible when you enforce them.
