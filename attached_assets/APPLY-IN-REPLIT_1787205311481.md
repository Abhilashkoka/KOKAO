## Apply

Upload the patch to your Repl's root, then in the Replit shell:

```bash
git checkout -b feat/prompt-kit-script-variants
git am kokao-script-variants.patch        # keeps the commit message
```

If `git am` complains, `git apply kokao-script-variants.patch` works too — it
just leaves the changes unstaged for you to commit yourself.

## Then, in order

```bash
pnpm install
pnpm --filter @workspace/db run push-force    # adds variant_key + 2 indexes
pnpm --filter @workspace/api-spec run codegen # no-op: output is committed
pnpm run typecheck:libs
```

That's exactly what your `scripts/post-merge.sh` runs, so if Replit fires the
post-merge hook you can skip it.

Then hit the run button and let the four validation workflows go
(`test`, `typecheck`, `codegen-drift`, `spec-lint`).

## Load the new prompts

The migration adds the *plumbing*; the prompt text ships as data.

```bash
cd artifacts/api-server
pnpm exec tsx scripts/export-prompt-kit-bundle.ts > /tmp/bundle.json
```

`scripts/prompt-kit-bundle.json` is already committed if you'd rather just use
that. Either way: **Admin → Prompt Kit → Transfer → Import**.

Versions land as `draft`, not `production` — deliberately. An import that
promoted itself would replace your live prompt everywhere it touched. Compare
old against new in the playground, then promote when you're happy. Rollback is
promoting the previous version; it just repoints a pointer.

## Production database

`push-force` is fine for dev. For a database holding real prompt data, use the
reviewed migration instead:

```bash
psql "$DATABASE_URL" -f lib/db/sql/2026-08-20_prompt_case_variant_key.sql
```

Nullable column, no default, no table rewrite — every existing row reads as its
flow's base case, which is the pre-variant behaviour. Idempotent; both were
verified against a real Postgres 16.

If the first index errors on a uniqueness violation, you already have two active
cases bound to one flow. That was ambiguous before this change too (resolution
silently took the lowest id). The SQL file has the query to find them.

## Two behaviour changes worth knowing about

**`cleanScript` collapses whitespace now.** Bracket removal used to leave the
spaces behind — `"start.  The  real"` — which read as a stutter in TTS. One
existing test asserted the doubled spaces; it's updated in the patch.

**The spokesperson response gained fields.** It still returns `script` as
before, so nothing that reads only that breaks. `beats` is *omitted* rather than
empty when the model returns a flat script, so "no production doc" and "a doc
with no beats" stay distinguishable.
