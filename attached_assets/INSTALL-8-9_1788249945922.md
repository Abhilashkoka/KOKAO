## 8 — Never run both lip-sync passes on one job

Two lip-sync passes existed with nothing stopping both from running on the same
video: the character engine's own per-shot pass, and the optional Studio
finishing pass. A character video with both enabled paid twice and had its
mouths redrawn twice.

The character pass now wins where both apply, and the optional one is refused
with a message naming the reason — the fix is un-ticking a box the user can
see. On Guided Story and every other engine nothing changes; the optional pass
is the only pass there.

Why the character pass wins is about inputs, not preference:

| | character pass | studio pass |
|---|---|---|
| audio | original narration PCM | re-extracted from the composed cut — carries the music bed, two loudnorm passes, an AAC round trip |
| granularity | one call per shot | one call spanning the whole runtime, across every cut |
| encode loss | purpose-encoded input | re-encodes an already-encoded composite |

## 9 — Face pixels on generated character shots

The uploaded-source path has enforced a face-pixel floor since the first
repair. The character path never got it, so generated shots reached the model
at whatever the video provider returned — often 480p. The model works on a
small square crop around the face; that crop was starved before it started.

Folded into `trimClipToStart`, which every shot already passes through, so the
mouth region takes one encode rather than two. Capped at 2x, same as the upload
path.
