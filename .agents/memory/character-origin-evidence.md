---
name: Character origin evidence
description: Keep origin independent of billing and selection, preserve real-photo ancestry, and scope strict fictional evidence to provider policy.
---

Origin evidence comes from server-observed successful generation and exact artifact bytes, not a description, a client-supplied source flag, visual inspection, or payment alone. Selecting a saved character does not change its origin.

**Why:** Older library characters could have approved sheets and outfits yet lack generation evidence. Requiring a wallet receipt also excludes valid quota/credit-funded creation.

**How to apply:** Preserve a separate origin record and freeze its identity with the consumed references. Provider request IDs are optional and must never be fabricated. Recover old evidence only from exact tenant-owned authoritative generation history; unknown stays unknown otherwise.

Image edits retain their input ancestry. An uploaded real-person image cannot become verified fictional origin simply because an AI generated its outfit or sheet.

**Why:** Applying fictional-only provider policy globally breaks legitimate approved-photo workflows, while dropping parent ancestry can wrongly allow them into fictional-only providers.

**How to apply:** Apply strict fictional evidence requirements at the relevant provider boundary; retain existing approval/consent rules elsewhere. Reuse the original ready-checkpoint evidence during finalization instead of recapturing it with a new timestamp.

Retrying a later step must not recreate the origin of an already saved, byte-identical portrait.

**Why:** A sheet-only retry can repeat the library-promotion step. Treating that as a fresh origin claim changes capture time and parent context, so strict immutable comparison blocks the retry.

**How to apply:** Verify the existing operation, tenant, owned asset IDs, and exact bytes before reusing its origin. Keep strict collision rejection for changed assets; preserve existing sheet state only on true reuse, not on a new customization.
