# Topic-video visual uniformity

- **Character costume is fixed for the whole video unless the user wrote wardrobe notes.** Enforced in two layers in the scene director: the prompt branches on trimmed notes (no-notes prompt has no "story calls for a change" escape hatch), and the parser hard-clamps every scene's outfitId to the locked outfit when notes are absent or whitespace-only. The parser clamp is the real guarantee — prompt-only fixes fail when the model ignores instructions. With real notes, only valid saved outfit IDs are accepted; unknown assignments fall back to the selected outfit.
- **Freeze the full saved wardrobe at enqueue for every character job.** Planning, preview rerolls, approval, and retries must resolve outfit IDs and reference paths from that snapshot. Live wardrobe edits must not change an already-created storyboard.
- **AI b-roll consistency is style-only, never first-image anchoring.** The Art Director returns one style clause appended to every scene's image prompt (length-bounded ~200 chars). Do NOT anchor b-roll scene N on scene 1's image the way character keyframes anchor on the outfit photo: b-roll subjects are supposed to differ per scene, and image anchoring drags subject content along with palette. Character identity, by contrast, IS image-anchored (keyframes are edits of the outfit reference photo) and needs no seed tricks.
- **Cohesion must not become repetition.** Keep a shared palette/light/lens treatment, but require consecutive B-roll shots to differ in at least two of subject, setting, shot scale, composition, movement, or visual category. Apply this at runtime in both planning and prompt-polish stages so an older editable template cannot silently weaken the sequence rule.
- **Never knowingly accept a repeated generated frame.** Compare each generated storyboard image with earlier frames using a conservative visual fingerprint. Retry a near-duplicate once with forced composition changes; if it still matches, fail/refund rather than render it.
- **Do not resend still-scene prose when animating a character keyframe that will be lip-synced.** The keyframe already embodies that prose; repeating emotional language makes the video model re-act the beat and drift the eyes/brows. Preserve the chosen motion instruction, add an explicit relaxed-expression hold, and let the downstream lip-sync replace mouth motion. Unsynced character shots may keep their scene prose with a lighter expression guard.
- Fail-soft is sacred here: missing/blank/wrong-type style leaves prompts byte-identical; planning failures fall back to narration-derived prompts with the same warning.
- Single-clip character text-to-video (characterClip) has no scenes, hence no uniformity problem; multi-scene treatment belongs to future storyboard work.

**Why:** the "or the story" prompt clause let characters change costume mid-video with no user request, mutable wardrobe rows let retries drift from reviewed work, independently-planned b-roll prompts drifted in palette/grade into a stock-collage look, a shared-look direction alone can make distinct scenes converge on the same generic composition, and re-sending a good keyframe's emotional prose caused expression escalation during image-to-video.
**How to apply:** when editing character planning or retry paths, carry the enqueue snapshot through every reference lookup and keep the parser clamp. For b-roll, never replace style-append with image anchoring and preserve adjacent-shot diversity. For character image-to-video prompts, distinguish downstream-lip-synced presenter shots from unsynced action shots.
